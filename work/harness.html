GF-Harness · 让研究工作跨模型、跨终端持续推进GF-Harness · A continuous workspace for AI research

我把模型、会话、执行工具与研究环境组织进同一套工作流：模型可以切换，任务上下文可以交接，多个 Agent 可以分工，代码修改、训练状态与实验结果能够在工作区中联动。GF-Harness 的重点是把一次对话延伸为可接续的研究过程——从资料调研与任务拆解，到代码实现、实验检查和文档交付，并让这些工作在桌面与移动端保持连续。I bring models, sessions, execution tools, and research environments into one workflow. Models can be switched, task context can be handed over, and agents can divide work while code changes, training status, and experiment results remain connected in the workspace. GF-Harness turns an isolated conversation into a continuing research process—from investigation and task decomposition to implementation, experiment inspection, and written deliverables—across desktop and mobile.

问题Problem

研究任务同时涉及模型对话、Linux 环境、版本管理、数据处理、训练作业和协作文档。工具和会话分散时，切换模型或终端往往意味着重新整理上下文。Research spans model conversations, Linux environments, version control, data processing, training jobs, and collaborative documents. Fragmented tools and sessions make changing models or devices an exercise in reconstructing context.

多 Provider 与账号管理Providers and accounts

统一接入 OpenAI、Anthropic 等模型后端，组织 API / Proxy 与账号配置，在任务过程中切换模型。模型适配与工作区逻辑分开，便于同一研究任务使用不同模型的能力。Connect model backends including OpenAI and Anthropic through API and proxy configurations, with provider and account selection during a task. Keep backend adaptation separate from workspace logic so a research task can draw on different models.

会话不是一次性上下文Sessions that carry work forward

支持会话分支、历史管理与 Session Handoff，将对话历史和任务状态交给后续模型或 Agent，使调研、实现与核验可以沿着已有工作继续推进。Support branches, history management, and session handoff, carrying conversation history and task state to another model or agent so investigation, implementation, and verification can continue from existing work.

分层 Agent 协作Hierarchical agent collaboration

通过 Harness 协议组织任务委派、子 Agent 分工、工具调用和结果交接，让不同模型参与同一项任务的调研、实现与复核。在实际研发工作中组织过十余个主 Agent、各约十个子 Agent 的分层协作。Use the harness protocol to organize delegation, subagent responsibilities, tool calls, and result handoff across models. In actual research workflows, I have organized more than ten main agents, with around ten subagents per main agent.

可组合的工具与 SkillsComposable tools and skills

支持自定义 MCP 连接、预设指令与 Skills 组合，把任务所需的工具和上下文组合进可复用工作流；连接飞书文档读写、机器人协作与经授权的资料检索，支持多语言翻译。Configure custom MCP connections, task presets, and skill combinations to assemble tools and context into reusable workflows. Integrate Feishu document operations, bot collaboration, authorized knowledge access, and multilingual translation.

连接真实执行环境Connected to the execution environment

集成 Linux Bash、Git 与文件工作区，连接 Docker、训练与数据平台以及 W&B 实验追踪。Agent 可以围绕代码、作业状态、运行日志和实验指标完成问题定位、修改与验证，使用者可在同一工作区审阅变更和跟踪进度。Integrate Linux Bash, Git, and file workspaces with Docker, training and data platforms, and W&B experiment tracking. Agents can use code, job status, logs, and experiment metrics to investigate problems, make changes, and verify outcomes, while the user reviews changes and follows progress in the same workspace.

桌面与手机，接续同一项工作One workflow across desktop and mobile

同步会话、工作区与输入草稿，支持语音输入；在移动端完成项目与分支切换、Git 历史查询、任务接续及训练状态查看，把研究工作台延伸到桌面之外。Synchronize sessions, workspaces, and input drafts, with voice input on mobile. Switch projects and branches, inspect Git history, resume tasks, and check training status beyond the desktop.

我在持续研究的问题The questions I keep working on

这个项目让我持续思考：如何让不同模型共享足够的任务上下文，却不把会话变成无边界的信息堆积；如何把 Agent 的工具调用接到真实研发环境，并让使用者能够理解、检查和接续其工作。This project keeps me thinking about how different models can share enough context without turning a session into an unstructured accumulation of information, and how agent actions can connect to real development environments in ways a user can inspect and continue.

Agentic Science / Full-stack Control

Programmable control for trapped-ion experiments

I independently developed an instrument-control stack spanning PCB design, embedded firmware, device drivers, communication protocols, APIs and experimental interfaces. A unified API coordinates dozens of heterogeneous instruments through reusable configuration, scanning, acquisition and calibration routines. Selected calibration routines are exposed to a prototype experimental agent as tools with explicit parameter constraints.

The problem

Trapped-ion experiments require coordinated control of lasers, RF sources, cameras, photon counters and sequencers. Coupled parameters make isolated scripts difficult to reuse, while drift and loss of lock interrupt acquisition. The control system must manage physical constraints, instrument states and experimental timing, with defined responses to faults.

My contribution and implementation

  • Independently designed PCBs and embedded/FPGA interfaces, and developed device drivers, communication protocols, APIs and user interfaces. Modules are organized around device capabilities, allowing experimental procedures to be reused when instruments change.
  • Implemented reusable procedures for laser longitudinal-mode maintenance, PDH relocking, atomic spectroscopy, quantum-state phase calibration and data acquisition, with explicit handling of device dependencies, asynchronous events and error responses.
  • Exposed instrument operations as Function Tools with typed inputs, parameter bounds, state preconditions and structured error responses. Combined these tools with Skills to support selected calibration, parameter maintenance, data fitting and result assessment tasks in the agent prototype.
  • Implemented state checks, parameter bounds, hardware interlocks and execution logging. Faults that cannot be recovered automatically are referred to an operator, with records retained for diagnosis.

Experimental procedures and tool orchestration

Experimental scripts or an agent invoke predefined tools and procedures, supply parameters and receive structured observations.

Instrument APIs and device drivers

A unified API exposes parameter settings, status queries, scans and data acquisition; device-specific drivers implement the corresponding instrument commands.

Deterministic hardware execution

PCBs, embedded firmware and FPGAs handle physical signals, timing and real-time control. LLM-based orchestration remains outside the nanosecond control path.

Experimental validation

The system is used for routine operation and calibration of trapped-ion experiments. The current agent prototype supports selected instrument operations. Complex fault diagnosis, long-term memory and AutoResearch workflows that formulate hypotheses and schedule experiments remain future research directions.

Related team hardware platform

The modular RISC-V / PXIe chassis illustrates the related QuCtrl-BELL team platform. The unified device software and experimental tools above are my independent full-stack work; the collaborative real-time feed-forward research is presented in Bell Ctrl.

What comes next?

  • A model can explain physical principles; can it also use live observations to decide what to measure next? I am studying device-state modeling, diagnostic action selection and the reuse of knowledge from previous faults.

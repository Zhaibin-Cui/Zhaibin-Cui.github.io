让真实量子实验成为可编程工具Making quantum experiments programmable

从 PCB、嵌入式固件和设备驱动，到统一通信协议、API 与实验界面，独立完成量子实验测控栈。让数十台异构仪器共享可组合的操作入口，并把部分日常校准接入带参数约束的 Agent 工具调用。I built the instrument-control stack across PCB design, embedded firmware, drivers, a unified protocol, APIs and experiment interfaces. It gives dozens of heterogeneous instruments composable operations and exposes selected calibration routines as constrained tools for an experimental Agent.

要解决的问题The problem

一套实验往往跨越激光、射频、相机、光子计数器和时序设备。设备参数相互依赖，单机脚本难以复用，漂移与失锁又会打断长时间采集。真正的难点是把物理约束、设备状态和实验流程放进同一个可靠的执行系统。Experiments span lasers, RF sources, cameras, photon counters and sequencers. Their parameters are coupled, isolated scripts are difficult to reuse, and drift or loss of lock interrupts acquisition. The hard part is expressing physical constraints, device state and experimental procedures in one reliable execution system.

我的工作与实现My contribution and implementation

  • 独立设计 PCB、嵌入式与 FPGA 接口，实现驱动、通信协议、API 和 UI，以设备能力为边界组织模块，支持替换仪器而复用实验流程。Designed PCBs, embedded and FPGA interfaces, drivers, protocols, APIs and UIs independently. Modules expose device capabilities so instrument changes do not require rewriting complete experiment procedures.
  • 把激光纵模维护、PDH 重新锁定、原子谱线扫描、量子态相位标定与数据采集封装为可复用流程，处理设备依赖、异步事件与异常返回。Packaged laser mode maintenance, PDH relocking, spectroscopy, quantum-state phase calibration and acquisition into reusable procedures, handling device dependencies, asynchronous events and error returns.
  • 将仪器能力暴露为带类型、参数范围、前置状态和异常返回的 Function Tools，结合 Skills 让 Agent 执行部分校准、参数维护、数据拟合和结果判断。Exposed instrument capabilities as Function Tools with typed inputs, parameter ranges, preconditions and structured errors. Skills let the Agent execute selected calibration, maintenance, fitting and result-interpretation routines.
  • 在执行层加入状态检查、参数边界、硬件互锁与日志。无法自动恢复时转交人工处理，使实验自动化有可追踪的执行记录。Added state checks, parameter bounds, hardware interlocks and logs. Failed automatic recovery escalates to a human, leaving traceable execution records.

实验意图与工具编排Experiment intent and tool orchestration

实验脚本或 Agent 选择已定义的工具与流程，传入参数并接收结构化观测。Scripts or an Agent select defined tools and procedures, pass parameters and receive structured observations.

协议与设备能力层Protocol and device capabilities

统一 API 描述参数设置、状态读取、扫描和采集，驱动负责适配各类仪器。A unified API describes configuration, state reads, scans and acquisition. Drivers adapt each instrument.

确定性硬件执行层Deterministic hardware execution

PCB、嵌入式与 FPGA 负责物理信号、时序与实时控制；LLM 不进入纳秒级控制路径。PCBs, embedded logic and FPGAs own physical signals, timing and real-time control. The LLM stays outside the nanosecond timing path.

实验验证Experimental validation

系统用于真实离子实验的日常运行与标定。当前 Agent 原型支持部分仪器操作；复杂故障诊断、长期记忆和从假设到实验的 AutoResearch 闭环属于后续研究。The system supports daily operation and calibration of real ion experiments. The current Agent prototype covers selected instrument actions. Complex diagnosis, long-term memory and an AutoResearch loop from hypothesis to experiment remain research directions.

下一步，追问什么？What comes next?

  • 模型能解释物理原理，是否也能根据现场观测判断下一次应该测什么？我正在把这个问题拆成设备状态建模、排查动作选择和故障经验复用。A model may explain the physics, but can it decide what to measure next from live observations? I decompose this into device-state modeling, diagnostic action selection and reuse of failure experience.

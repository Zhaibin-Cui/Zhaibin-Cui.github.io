MiniMax｜大规模预训练、Scaling 与数据研究MiniMax | Large-scale pretraining, scaling, and data research

在 MiniMax 参与大规模 GPU 集群上的预训练算法研究，工作覆盖多级 Scaling Ladder、Scaling Law、Benchmark 与 BPB 评测、Document Packing、数据混合及数据管线协作。重点是把数据与训练策略转化为可比较的实验：明确模型规模和训练预算，追踪损失、任务表现与有效吞吐，并判断小规模观察能否在更大训练规模保持。At MiniMax, I work on pretraining algorithms in large GPU-cluster settings, contributing to model ladders, scaling analysis, benchmark evaluation, document packing, data mixtures, and the supporting data pipeline. My focus is to turn data and training choices into comparable experiments: specify the model scale and training budget, track loss and task-level behavior alongside effective throughput, and examine whether conclusions from smaller runs remain useful at larger scales. BPB is one evaluation method within this work.

大规模 GPU 训练与多级 Scaling LadderLarge-scale GPU training and model ladders

参与大规模 GPU 集群预训练与多级模型实验，围绕小、中、大三个尺度组织数据配方和训练配置的对照。Ladder 用于以较小实验成本筛选假设，再观察较大规模下的训练行为；各尺度需要明确参数规模、训练 Token、批量和学习率调度等实验条件。I participate in large-scale GPU pretraining and a small/intermediate/large model ladder, comparing data mixtures and training configurations across scales. The ladder provides lower-cost tests of a hypothesis before examining larger-scale behavior, with model size, training tokens, batch size, and learning-rate schedules specified for each experiment.

Scaling Law 研究把参数规模、数据量与计算预算联系起来：比较不同配方的损失随规模变化的趋势，区分对已有实验点的拟合与对未参与拟合规模的外推。关注的不是单次最优分数，而是同一训练选择在不同规模和训练阶段是否仍然有利。Scaling analysis relates parameter count, data volume, and compute budget. I examine how loss changes with scale under different data recipes, distinguishing fits to observed runs from extrapolation to held-out scales. The question is whether a training choice remains favorable across model sizes and stages, rather than whether one run has the best final score.

观察指标包括训练与验证损失、Benchmark 表现、有效 Token 吞吐、训练稳定性，以及配方排序和外推误差。Chinchilla 与 OLMo-ladder 提供公开方法参考，不代表公司的模型配置、内部结果或采用了完全相同的实现。Relevant measurements include training and validation loss, benchmark results, effective-token throughput, training stability, recipe rankings, and extrapolation error. Chinchilla and OLMo-ladder are public methodological references, not disclosures of company configurations, internal results, or an identical implementation.

Benchmark 与按字节归一化的 BPB 评测Benchmark evaluation and byte-normalized BPB

参与预训练 Benchmark 与评测 Pipeline 建设，围绕 Checkpoint、数据域和训练配方组织评估。任务指标用于观察知识与推理表现，损失类指标用于追踪模型对指定文本分布的预测能力；二者承担不同的判断任务。I contribute to pretraining benchmarks and evaluation pipelines organized around checkpoints, data domains, and training recipes. Task metrics assess knowledge and reasoning behavior, while loss-based metrics track predictive performance on a specified text distribution. They provide complementary evidence.

BPB（Bits-per-Byte）是一种评估方法：将被评分文本的 Token 负对数似然累加，以 2 为对数底，并除以该文本的 UTF-8 字节数。若 NLL 使用自然对数，则 BPB = NLL /（ln 2 × 字节数）；不把仅作为上下文的 Token 或未评分的 Padding 计入对应分子与分母。Bits-per-byte (BPB) is an evaluation method: sum the token negative log-likelihood of the scored text in base 2 and divide by its UTF-8 byte count. When NLL uses natural logarithms, BPB = NLL / (ln 2 × byte count). Context-only tokens and unscored padding must not enter the corresponding numerator or denominator.

比较时保持文本内容、规范化方式、上下文窗口、边界处理和评分掩码一致，并明确聚合方式。BPB 减少 Tokenizer 粒度差异造成的量纲问题，但不会自动消除分词或评测协议的影响；需要结合分域结果和任务指标解释变化。Comparisons keep text content, normalization, context windows, boundary handling, and scoring masks consistent, with the aggregation rule made explicit. Byte normalization reduces the unit mismatch caused by token granularity; it does not eliminate tokenizer or evaluation-protocol effects. Domain-level results and task metrics remain necessary to interpret changes.

BPB = −∑t ∈ S ln pθ(xt | x<t)ln 2 · BS

S 为实际计分的 Token 集合，B_S 为其对应原始文本的 UTF-8 字节数；语料整体按总 NLL/总字节数聚合，与逐文档 BPB 的简单平均不同。S denotes scored tokens and B_S the UTF-8 byte count of the corresponding original text. Corpus-level total NLL divided by total bytes is different from an unweighted mean of document BPB values.

Document Packing、数据混合与质量分层Document packing, data mixtures, and quality tiers

围绕文档边界、长度分布和 Padding 策略开展 Packing 对照，研究样本构造如何同时影响计算利用率和语言建模任务。需要区分物理上把文档放入同一序列，与模型是否允许跨文档使用上下文：Attention Mask、Position ID 和 Loss Mask 决定实际训练语义。Packing experiments examine document boundaries, length distributions, and padding strategies as both a compute-utilization problem and a language-modeling choice. Placing documents in one sequence is distinct from allowing cross-document context: attention masks, position IDs, and loss masks determine the actual training semantics.

结合领域分类、质量分层、分桶采样、Data Mixture 与数据增强，比较语料的内容组成和呈现方式。公开的 Nemotron 数据工作提供了质量分类、去重与合成数据等方法参考；实际配方的价值仍需通过同预算训练与评测来判断。The work combines domain classification, quality tiers, bucketed sampling, data mixtures, and augmentation to examine both corpus composition and presentation. Public Nemotron work provides references for quality classification, deduplication, and synthetic data. A recipe's value still has to be established through controlled training and evaluation at comparable budgets.

同时观察有效 Token 比例、Padding 占比、序列长度分布、训练吞吐与分域验证损失，避免把更多有效训练 Token 带来的收益直接解释为数据语义质量提高。对于配方对比，记录各数据源的采样权重与实际训练暴露量。Measurements include effective-token fraction, padding fraction, sequence-length distribution, training throughput, and domain-level validation loss. Gains from processing more useful tokens should be separated from gains in semantic data quality. Mixture comparisons also track sampling weights and the actual training exposure of each source.

参与预训练数据管线开发与联调Contributing to the pretraining data pipeline

参与语料预处理、Tokenization、数据分片、Document Packing 与 DataLoader 的开发和联调，把候选数据策略接入已有的工业训练流程。工作对象是从文档到模型实际消费的训练样本之间的接口与处理逻辑。I contribute to development and integration across corpus preprocessing, tokenization, data sharding, document packing, and data loading, connecting candidate data strategies to an existing industrial training workflow. The focus is the transformation from source documents to the samples actually consumed by training.

联调需要核对 Token 与样本数量、分片和索引的一致性、文档边界及掩码行为，并结合训练端复核数据分布。这样才能判断观察到的差异来自数据策略本身，还是来自样本构建、加载或评测口径变化。Integration requires checking token and sample counts, shard/index consistency, document boundaries, and masking behavior, then verifying the consumed data distribution from the training side. This helps distinguish a data-policy effect from a change in sample construction, loading, or evaluation.

关注数据准备与读取吞吐、实际采样分布、训练输入一致性，以及数据版本、训练配置与 Checkpoint 之间的可追溯关系。通过预训练对照和 Benchmark 评测，为数据配方迭代提供依据。Relevant checks cover preparation and loading throughput, realized sampling distributions, input consistency, and traceability between data versions, training configurations, and checkpoints. Controlled pretraining runs and benchmark evaluation provide the evidence for iterating on data recipes.

对照实验与跨尺度结论稳定性Controlled experiments and cross-scale stability

研究中的核心问题是：某个数据或训练选择在小规模上有效，究竟是稳定趋势，还是预算、阶段和评测设置的产物？因此将模型规模、训练预算、数据配方和 Checkpoint 位置放在同一实验记录中，避免把不同条件下的最终分数直接比较。A central question is whether a choice that helps a smaller run reflects a stable trend or a particular budget, training stage, or evaluation setup. Model scale, training budget, data recipe, and checkpoint position therefore belong in the same experimental record, rather than being hidden behind final-score comparisons.

比较损失曲线和分域能力变化时，尽量保持其余变量一致，明确 Token 预算与计算预算各自控制了什么。计算量需要结合具体架构、序列长度和执行策略核算：分别说明前向、反向、激活重计算与优化器更新的统计范围，区分 MoE 每个 Token 激活的计算与总参数所需的状态存储。Attention 的工作量还取决于实际序列结构、掩码及具体实现，不能仅由参数量和 Token 总数概括。Loss and domain-level comparisons keep other variables as consistent as possible and distinguish token-budget controls from compute-budget controls. Compute accounting depends on the architecture, sequence lengths, and execution policy: the scope should specify forward and backward passes, activation recomputation, and optimizer updates. For MoE, per-token active computation is distinct from state storage for the full parameter set. Attention work also depends on sequence structure, masks, and implementation; parameter count and total tokens alone are insufficient.

FLOPs、Token 吞吐与实际耗时回答不同问题。FLOPs 报告需要说明是模型理论计算还是包含重计算等额外工作的执行口径；Token/s 需要明确有效或实际处理 Token、全局或单卡口径；Wall Time 则包含未被重叠隐藏的通信、数据读取与同步等待。基于一致口径分析整体趋势、任务差异和配方排序反转，并用未参与拟合的规模或训练阶段检验外推。FLOPs, token throughput, and elapsed time answer different questions. FLOP reports should distinguish model-operation estimates from execution accounting that includes additional work such as recomputation. Tokens per second requires a defined numerator—effective or processed tokens—and global or per-GPU scope. Wall time also reflects exposed communication, data loading, and synchronization. With these definitions aligned, overall trends, task differences, and recipe-rank reversals can be compared, and extrapolation tested on held-out scales or training stages.

这些分析服务于下一轮实验选择：哪些假设值得放大验证，哪些现象需要补充对照，哪些指标之间存在取舍。公开的 OLMo-ladder 将中间损失特征与任务表现分开建模，提供了理解这一问题的方法参考。The analysis informs which hypotheses deserve larger-scale tests, which observations need additional controls, and where metrics trade off against one another. OLMo-ladder's separation of intermediate loss features from task performance is a useful public methodological reference for this problem.
